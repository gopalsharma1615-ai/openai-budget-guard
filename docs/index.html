OpenAI Budget Guard

Give each OpenAI API key a token or cost budget, for the key as a whole or for one task. Every request is checked before it is sent and metered after it returns. When a budget runs out, the request never reaches OpenAI and the app gets a clear "budget exhausted" error.

Per-key budgetsPer-task budgetsInput / cached / output tokens USD cost limitsHourly → monthly windowsStreaming Python SDK + any-language proxy

A five-minute script for showing it live. Each step lists what to run, what the audience sees and what to say. Start with --mock (no network, no spend), then repeat with a real key.

Step 1 · Allot budgets to one key

One key gets a key-wide cap and two task-specific caps.

python · examples/demo.py
guard.set_budget(key, "*",         max_cost_usd=0.01, label="demo")   # aggregate: 1 cent across all tasks
guard.set_budget(key, "summarize", max_output_tokens=400)           # individual: summarize may emit 400 tokens
guard.set_budget(key, "qa",        max_input_tokens=2_000)          # individual: qa may read 2k input tokens

Say: "This is the same OpenAI key. Each team or feature gets its own allowance, and the whole key also has a hard dollar ceiling."

How it works

The guard sits between your app and OpenAI as an httpx transport (in Python) or as a small proxy (for any language). Each metered request goes through five steps.

01
IdentifyReads the key from the Authorization header and stores only a hash of it. The task comes from the client setting or the X-Budget-Task header.
02
EstimateCounts prompt tokens with tiktoken and adds max_tokens (or 512) for output. This gives the worst-case cost of the request.
03
Check & reserveChecks the task budget and the key-wide budget in one atomic step. If both pass, the estimate is held in the ledger.
04
ForwardSends the unchanged request to OpenAI. Streaming responses are passed through as they arrive.
05
MeterReads the actual usage from the response, splits it into input, cached and output tokens, prices each part and replaces the estimate.

If step 03 fails: nothing is sent to OpenAI and the app gets HTTP 429 with a budget message. If OpenAI returns an error: the reservation is released, because failed calls are not billed.

Concepts

Key

Identified by sha256(key)[:16]. The raw key is never written to disk. Reports show sk-...abcd or a label you choose.

Task

Any name you pick, such as summarize, rag or client-demo-3. Usage is recorded per task so you can see where the money went.

Budget

A set of limits attached to a key and a task. Task * means all of the key's tasks combined.

Limits

Any combination of max_cost_usd, max_total_tokens, max_input_tokens, max_cached_tokens and max_output_tokens.

Period

none (lifetime), hourly, daily, weekly or monthly. Windows reset on UTC boundaries.

Ledger

A SQLite file (WAL mode) with one row per request. It is shared safely across threads and processes. Location: $OBG_DB or ~/.openai_budget_guard/usage.db.

The three token types

TypeWhat it isComes fromPriced at
InputPrompt tokens that were not served from OpenAI's prompt cacheprompt_tokens − cached_tokensinput rate
CachedPrompt tokens served from the prompt cache (repeated prefixes)prompt_tokens_details.cached_tokenscached rate (usually 50–90% cheaper)
OutputGenerated tokens, including hidden reasoning tokenscompletion_tokens / output_tokensoutput rate

Both usage formats are understood: Chat Completions and Embeddings (prompt_tokens) and the Responses API (input_tokens).

Individual vs aggregate budgets

A request must pass every budget that applies to it: its own task's budget and the key-wide * budget. Either one can block it.

Key sk-...abcd · task * · max $5.00 / month (aggregate)
summarizemax 50,000 output tokens
qamax 200,000 input tokens / day
ragno own budget, so only the $5 cap applies

Individually exhausted

summarize hits 50k output tokens. Only summarize is blocked. qa and rag keep working.

Aggregately exhausted

All three tasks together reach $5. Every task on this key is blocked until the next monthly window or until you raise or reset the budget.

Keys are fully independent. Exhausting one key never affects another.

What the app sees when a budget runs out

The response is shaped like a normal OpenAI error, so any OpenAI SDK (Python, JS, Go, ...) raises it as usual. The status is 429 with x-should-retry: false, so the SDK raises immediately and does not retry.

cost_budget_exhausted

Cost budget exhausted for OpenAI key sk-...abcd, all tasks combined, monthly window: used $5.0012 of $5.0000.
token_budget_exhausted

Token budget exhausted for OpenAI key sk-...abcd, task 'summarize': used 50,183 output tokens of 50,000 output tokens.
token_budget_exhausted · preflight

Token budget insufficient for OpenAI key sk-...abcd, task 'qa': this request may need up to 4,000 output tokens but only 1,250 output tokens of 10,000 output tokens remains.
no_budget_allotted · only with require_budget=True

No budget allotted for OpenAI key sk-...abcd; requests are refused until one is set.

    r = client.chat.completions.create(model="gpt-4o-mini", messages=msgs)

Ways to integrate

guarded_openai() returns a normal openai.OpenAI client. The rest of your code stays the same.

python
from openai_budget_guard import BudgetGuard, guarded_openai, for_task

guard = BudgetGuard()                                    # uses $OBG_DB or ~/.openai_budget_guard/usage.db
guard.set_budget(key, "*", max_cost_usd=5, period="monthly", label="sales-demo")
guard.set_budget(key, "summarize", max_output_tokens=50_000)

client = guarded_openai(key, task="summarize", guard=guard)
client.chat.completions.create(model="gpt-4o-mini", messages=[...])

rag = for_task(client, "rag")                           # same connection pool, billed to "rag"
rag.responses.create(model="gpt-5-mini", input="...")
rag.embeddings.create(model="text-embedding-3-small", input=docs)

client.chat.completions.create(..., extra_headers={"X-Budget-Task": "qa"})  # one-off task
python
# asyncio
from openai_budget_guard import guarded_async_openai
client = guarded_async_openai(key, task="chatbot")
stream = await client.chat.completions.create(model="gpt-4o", messages=msgs, stream=True)

# LangChain (or anything else that accepts an httpx client)
import openai
from langchain_openai import ChatOpenAI
from openai_budget_guard import BudgetGuard, BudgetTransport

llm = ChatOpenAI(model="gpt-4o-mini",
                 http_client=openai.DefaultHttpxClient(transport=BudgetTransport(BudgetGuard(), "langchain-demo")))

Accuracy & safety guarantees

No overshoot under concurrency

The check and the reservation happen in a single BEGIN IMMEDIATE SQLite transaction. In the test with 20 threads racing a budget that fits 5 calls, exactly 5 succeed.

Real usage, not guesses

The worst-case estimate is used only for the pre-check. After each response, the ledger row is replaced with OpenAI's reported usage.

Streaming handled

Streamed chat requests get stream_options.include_usage added. If your code didn't ask for it, the extra usage chunk is removed, so loops like chunk.choices[0] keep working. For the Responses API, usage is read from response.completed.

Failures aren't charged

An upstream 4xx/5xx or a network error releases the reservation. A stream abandoned before usage arrives keeps its estimate and is marked estimated.

No retry storms

Blocked responses carry x-should-retry: false, so the OpenAI SDK's automatic retries don't hammer an exhausted budget.

Keys never stored

Only a SHA-256 prefix and a sk-...abcd hint are kept. The proxy's status endpoint shows a key only its own budgets.

Limits & notes

Metered endpointschat/completions, responses, embeddings and completions. Everything else (files, models, batches, ...) passes through unmetered.
Not pricedImage generation, audio and realtime usage.
OvershootWithout max_tokens, 512 output tokens are assumed. A response that produces more than that can push a budget slightly over once. After that, every request on that budget is blocked.
Token estimateText only. Image inputs are not counted in the pre-check, but they are counted in the actual usage.
Sharing a budgetWorks across processes on one machine through a shared SQLite file. For several machines, run one proxy and point everything at it.
HTTPS proxyThe Python transport honours HTTPS_PROXY but not NO_PROXY.
